Treads Parsing
Privacy Policy

Last updated: 2 November 2026 · Current local application version

Treads Parsing is a tool for searching Threads posts by keyword, viewing posts and replies, and keeping a local research archive for editorial planning. The application is operated by individual entrepreneur Sergey Viktorovich Pogrebnyak. Contact: orgetheone@gmail.com.

1. Data the application processes

  • For the connected account: the Threads user ID and username returned by the Threads API.
  • For posts and replies available through the API: post or reply IDs, text, usernames, and links to the original content.
  • Search keywords, the source of a retrieved record, and the time when the application saves it locally.
  • A Threads access token supplied by the operator to authorize API requests.

Access depends on the account's authorization, token permissions, and Meta's approval and API restrictions. The application does not request account passwords, private messages, payment information, or contact lists. The current application does not publish posts or replies or modify a Threads account.

2. How data is used

Data is used to verify the connection, run searches requested by the operator, display posts and replies with their source links, and save or export research results. The purpose is to explore discussion topics for editorial planning. Data is not sold or used for advertising targeting or individual profiling.

3. Storage and retention

The current application runs on the operator's computer. Its access token is stored in a local .env configuration file. Retrieved records are saved in a local SQLite database, threads.sqlite3. Search and reply results may also remain in the running application's session. The operator can download CSV and JSON copies.

The application has no automatic expiration or deletion schedule. The operator is responsible for reviewing stored records and removing them when they are no longer needed for the stated purpose, when a valid deletion request is received, or when deletion is required by Meta or applicable law. Exported copies must be included in this review. Revoking access does not itself erase previously saved records.

4. Sharing and external services

Authorized API requests are sent to Meta's Threads API over HTTPS. The current version does not send retrieved content to an external AI service and does not provide an automatic third-party sharing feature. Exported files remain under the operator's control and are not automatically published by the application.

This policy page is a static page hosted on GitHub Pages. It contains no application token, research archive, analytics scripts, or forms. GitHub may process technical website access information under its own privacy statement. Meta processes API requests under its own policies.

5. Security

API connections use HTTPS. Tokens must be kept out of public repositories and screenshots. The local database and configuration file are not encrypted by the application; access to them depends on the computer's account permissions and security. If an access token is exposed, the operator should revoke or replace it.

6. Request access, correction, or deletion

Anyone whose data is processed by Treads Parsing may contact orgetheone@gmail.com with the subject “Treads Parsing — data request”. Provide your Threads username and, where relevant, links or IDs identifying the posts or replies concerned. Do not send passwords or access tokens.

The operator will use this information only to locate the records, verify the request where necessary, and respond. You may request information about your records, correction, or deletion from the application-controlled archive and exports. Requests will be handled without undue delay, subject to applicable requirements. Removing data from this application does not delete the original publication on Threads.

To remove all locally stored application data, the operator can stop the application, delete threads.sqlite3 and any CSV or JSON exports, and delete the token from .env. Closing the application clears its active session. Access can also be revoked in the connected account's Threads website-permissions settings.

7. Changes and contact

This policy describes the current version. If hosting, data use, or external AI processing changes, the policy must be updated before those changes are used. Questions and privacy requests: orgetheone@gmail.com.
